# Remove all `*Foreign` document types

## Context

Every domain in `program/src/document/` exports a `<Domain>Foreign` document type (e.g. `JsonForeign`, `XmlForeign`, …). Each follows an identical pattern: a `@document struct` with `value::Any` and `selection::Reference` fields, plus a one-line constructor.

Investigation shows these types are dead weight:

- **No projection, printer, reader, or IO map dispatches on any `*Foreign` type.** They are absent from every projection dispatch table (e.g. `JsonToSyntax`, `XmlToSyntax`).
- **No test references any `*Foreign` type** (`program/test/` is clean).
- The only non-definition references are the `using`/`export` re-exports in `program/src/Projectured.jl`, and template mentions in `guide/tutorial-new-domain.md`.

The user has confirmed these are not needed. Remove them entirely to shrink the public API surface and avoid the false signal in the new-domain tutorial that every domain must define one.

## Per-file changes (apply uniformly)

For each domain file listed above, make three deletions:

1. **Struct + constructor** — the 5-line block:
   ```julia
   @document struct <Domain>Foreign <: <Domain>Document
       value::Any
       selection::Reference
   end
   <Domain>Foreign(value) = <Domain>Foreign(Cell(value), Cell(nothing))
   ```
2. **Mutable type from the `export` list** — remove `<Domain>Foreign,` from the `export …` line(s) at the top of the module.
3. **Immutable type from the `export` list** — remove `I<Domain>Foreign,` from the same `export …` block.

Example for [program/src/document/Json.jl](program/src/document/Json.jl#L29-L30): drop `JsonForeign,` from line 29 and `IJsonForeign,` from line 30, then delete the struct/constructor at lines 60-64.
